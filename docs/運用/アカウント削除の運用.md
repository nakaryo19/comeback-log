# アカウント削除の運用

App Store Review Guideline 5.1.1(v)（アカウントを作成できるアプリは、アプリ内から削除できること）
への対応。実装は次の3つで構成される。

| 層 | 場所 |
|---|---|
| 画面 | `components/settings/AccountScreen.tsx` |
| 呼び出し | `lib/supabase/account.ts` |
| 実処理 | `supabase/functions/delete-account/index.ts`（Edge Function） |

## なぜ Edge Function が必要か

`auth.users` の行の削除には `service_role` キーが必要で、クライアントからは実行できない。
**`service_role` は RLS をすべて迂回する**ため、アプリのバンドルに含めてはならない
（含めれば、全ユーザーの感情ログを誰でも読める状態になる）。この処理だけをサーバー側に置く。

`auth.users` を消せば、`goals` → `sub_goals` → `tasks` → `emotion_logs` は `on delete cascade` で
連鎖削除される（`supabase/migrations/20260713000000_initial_schema.sql`）。
`public_profiles` も `user_id` 経由で同様に消える。**アプリ側で個別に消す処理は要らない。**

## デプロイ手順

Edge Function はリポジトリに置くだけでは動かない。**デプロイして初めて画面が機能する。**

```bash
# 初回のみ：Supabase CLI のインストールとログイン
brew install supabase/tap/supabase
supabase login

# プロジェクトの紐付け（<project-ref> は Supabase ダッシュボードの URL に含まれる）
supabase link --project-ref <project-ref>

# デプロイ
supabase functions deploy delete-account
```

### 環境変数について

`SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` は、Edge Function の実行環境に
Supabase が自動で注入する。**`supabase secrets set` で自分で設定する必要はなく、
`service_role` キーをローカルのファイルや `.env.local` に置く必要もない。**

## 動作確認

**本番アカウントで試さないこと。** 削除は取り消せず、無料プランにはバックアップも
Point-in-Time Recovery も無い（`docs/運用/バックアップ運用.md`）。

確認にはテスト用アカウントを新規に作り、次を順に見る。

1. 設定画面に、削除される件数（大目標・タスク・感情の記録）が表示される
2. 確認欄に「削除」と入力するまで実行ボタンが押せない
3. 実行後、ログイン画面に戻る
4. 同じメールアドレスで再登録でき、データが空の状態から始まる
5. Supabase ダッシュボードの Authentication → Users から、当該ユーザーが消えている
